## What this is

A free, universal "folder substrate" any business owner opens in Claude Code and builds
their entire Claude ecosystem inside. They write their business down once as small
labeled files; Claude reads them and does consistent on-brand work instead of starting
cold. Vertical-agnostic: works for a dentist, an agency, a coach, a manufacturer.

It is derived from a one-client deliverable at `/Users/johnhyland/Desktop/Dr. Dome Brain/`
(READ-ONLY reference: never modify it). That version has confirmed defects, all fixed by
this build.

## Non-negotiables

1. **Zero dependencies.** No pip installs, ever. Python tools use the standard library
   only. The folder must ALSO work as pure markdown if the user never touches Python.
2. **Real Claude Code layout.** Slash commands in `.claude/commands/*.md` WITH frontmatter
   (`description:` at minimum). Skills in `.claude/skills/<name>/SKILL.md` (auto-discovered),
   NOT a top-level Skills/ folder.
3. **No Obsidian.** No `.obsidian/`, no mention of it.
4. **No dental/client residue.** No "patient", "PHI", "practice", "Dr. Dome", "post-op",
   "molar", "hygiene recall", "sterilization" anywhere. Universal business language:
   customers/clients, team, processes.
5. **No dead references.** Every command, path, skill, and file mentioned in any doc must
   exist. The old version told users to "run build-kb" (does not exist). Grep for every
   promise you make and verify it resolves.
6. **Voice DNA (binding for every .md).** No em dashes, ever (use commas, colons,
   parentheses). No "This isn't X. It's Y." negation-then-correction patterns. No 3+
   consecutive fragments starting with the same word. No: leverage, utilize, harness,
   delve, robust, seamless, streamline, unlock, supercharge, game-changer, cutting-edge,
   straightforward, "let's dive in", "it's worth noting". Contractions on. Short
   paragraphs. Write like a sharp human explaining to a friend, not a language model.
7. **Beginner-proof.** The audience includes people who have never opened a terminal.
   Every shell command in every doc must be copy-pasteable, work from the repo root,
   survive paths containing spaces (quote them), and fail with plain-English messages,
   never a raw traceback.

## Design decisions already made (do not relitigate)

- **Label block fields.** Required: `id`, `title`, `type`, `summary`, `updated`.
  Optional: `owner`, `tags`, `aliases`, `status`, `source`. The field is `type`
  (NOT `note_type`). Types = principle, framework, model, playbook, template,
  decision, glossary, record. Folder names = plural forms as in the tree above.
  Docs, commands, examples, and tools must agree EXACTLY on this. `check.py`
  already enforces it; make every doc match the code.
- **Folders renamed** from the old version: `decision-rules/` -> `decisions/`,
  `case-notes/` -> `records/`, `_intake/` -> `_inbox/`.
- **/load retrieval order.** The command instructs Claude to: (1) read
  `Knowledge_Base/INDEX.md` and choose the right file(s) by title+summary using judgment,
  (2) fall back to `python3 tools/find.py "<query>" --json` only when INDEX.md is missing,
  stale, or too large to scan. Never blind-load the top keyword hit: keyword search
  returns wrong files on synonym queries ("money back" vs "refund", proven in testing).
- **/ingest contract.** Reads `_inbox/`, proposes a file list (folder + one-line summary
  each), STOPS for approval, then writes on approval, then runs
  `python3 tools/index.py` and `python3 tools/check.py` IF python3 exists (check with
  `command -v python3`; if absent, regenerate INDEX.md by hand from the files and say so).
  Keeps the owner's wording. Never invents steps. Replaces any real person's
  name/contact/account details found in source docs with a placeholder and tells the user.
- **/interview.** Topics inline in the command file (no external questions file):
  basics, voice, processes, rules, terms. One question at a time. Skips what CLAUDE.md
  and the KB already cover. Same post-write index/check behavior as /ingest.
- **/setup.** Reads CLAUDE.md, walks the user through each bracket conversationally
  (one question at a time), writes the completed file, then suggests the next step
  (drop docs in _inbox and run /ingest, or run /interview if nothing's written down).
- **Example files** carry the normal label block plus `status: example` and a one-line
  note in the body: this is an example showing the format, delete it once you have real
  files. They must pass `tools/check.py`. They are fictional and universal (a small
  services business, no vertical jargon).
- **CLAUDE.md** brackets: business name, what you do and for whom, tone with customers,
  tone with team, always/never lists, hard rules. Hard rules MUST include: never put
  real customer or employee personal data (names, contact info, account numbers, health
  or financial details) into files; keep this folder out of public repos and shared
  drives unless you've checked what's in it. Plus: read the relevant Knowledge_Base
  files before tasks that depend on process; ask instead of guessing; a pointer that
  new users should type /setup.
- **README.md** (the main deliverable John asked for) sections, in order:
  1. Name + one-line promise (what the folder does for you).
  2. "What this is": 2 short paragraphs. The write-it-down-once idea; works for any
     business; nothing to install beyond Claude Code.
  3. "What you get": the folder map with one-line explanations.
  4. "Install": three paths, each numbered and copy-pasteable:
     (a) Download ZIP from GitHub (no git needed) -> unzip -> open folder in Claude Code;
     (b) `git clone https://github.com/1DSLabs/ai-os-starter.git "My Business Brain"`;
     (c) Claude Code desktop app: open folder. Include the 60-second first session:
     type `/setup`.
  5. "Your first 10 minutes": /setup, then EITHER drop 2-3 existing docs into _inbox
     and /ingest, OR /interview if nothing's written down. Then ask Claude to do a real
     task and watch it use the files.
  6. "How it stays organized": one idea per file, label block, the 8 folders in a table.
  7. "The optional tools": index/check/find, one line each, "no installs, Python 3 which
     is already on your Mac; on Windows install Python from python.org or skip the tools
     entirely, everything works without them."
  8. "Keep it private": your business goes in here, so treat the folder like your
     books. Keep the repo private if you push it anywhere. What NOT to put in
     (customer/employee personal data).
  9. FAQ: 5-6 real questions (Do I need to code? What if I have no SOPs? Does my data
     get uploaded anywhere? Can my team use it too? What's the difference between a
     command and a skill? How do I update to a newer version?).
  10. "Who built this": two sentences, 1DS Collective, built from the system we run our
      own agency on. Link to 1dscollective.com. Light touch, no hard pitch.
- **START-HERE.md**: assumes they've installed and opened the folder. Walks the first
  session concretely: /setup transcript-style example, _inbox + /ingest walkthrough,
  what the finished KB looks like (point at the EXAMPLE files), how to write the first
  skill, when to bother with the tools. Ends with "as you grow" guidance (splitting
  shared vs location/brand-specific material) and the same privacy note, briefly.
- **selftest.py**: stdlib `unittest`. Cover at minimum: frontmatter parity cases (CRLF,
  smart quotes, colon-in-value, tab lists, inline lists, BOM, no-block, missing-colon
  error), index.py builds INDEX.md + _index.json on a temp KB and flags duplicate ids,
  check.py catches missing required fields and wrong-folder placement and passes the
  shipped EXAMPLE files, find.py ranks an exact-title match first and returns valid
  --json. Runnable as `python3 tools/selftest.py` from repo root AND from tools/.
